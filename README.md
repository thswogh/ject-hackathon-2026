# GAP

**선수와 나 사이의 차이(GAP)를 보고, 오늘 운동할 이유를 찾는 서비스.** (젝커톤 2026)

- 서비스: https://gap-motivation.vercel.app/
- 서비스 소개 페이지: https://gap-motivation.vercel.app/intro

## 서비스 소개

> 세상에서 가장 쓸데없는 비교로 시작해서, 오늘 밖으로 나갈 이유 하나로 끝나는 스포츠 서비스입니다.

응원하는 선수가 내 나이에 우승하고 국가대표가 된 걸 보면 "나는 뭐 했지" 싶어집니다. GAP는 그 비교를 장난으로 꺼내 웃게 만들고, 끝에는 오늘 10분짜리 운동 하나를 쥐여 줍니다. 로그인 없이 탭 몇 번이면 끝납니다.

**이렇게 써요**

1. **종목과 나이 입력** — 야구, 해외야구, 축구, 해외축구, NBA, e스포츠(LoL), 또는 아무거나.
2. **VAR 판독** — "주심이 직접 모니터로 갑니다" 같은 판독 연출이 나오는 동안 결과를 만듭니다.
3. **리빌** — "손흥민은 당신 나이에 챔피언스리그 결승에 선발로 나섰습니다. …당신은요?" 평균 은퇴 나이까지 남은 시간, 내가 태어난 해에 그 선수가 몇 살이었는지도 함께 보여줍니다.
4. **감정 선택** — 위로(늦게 피어난 선수 이야기), 동기부여(선수의 실제 습관), 신랄한 비판(이 앱 볼 시간에 나가서 뛰세요) 중 하나를 고릅니다.
5. **오늘의 처방과 선수 카드** — 10분 안에 할 수 있는 운동을 받고 스톱워치로 실행합니다. 질문 4개에 답하면 OVR과 등급이 찍힌 내 선수 카드를 이미지로 저장할 수 있습니다.

**AI는 이렇게 씁니다**

채팅창은 없습니다. AI는 화면 뒤에서 위로·동기부여·독설 문구와 처방을 매번 새로 쓰고, 선수·연도 같은 사실은 팀이 준비한 기록에서 가져와 틀린 기록이 나오지 않게 합니다. AI가 실패하거나 늦어도 준비한 문구로 넘어가서 화면은 멈추지 않습니다.

## 기술 스택

Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS 4 · OpenAI Responses API (`openai`, `zod` structured outputs) · html-to-image · Remix Icon · Vercel

로그인과 사용자 DB는 없습니다. AI가 웹에서 찾은 선수 기록만 Upstash Redis에 쌓습니다. OpenAI 키는 서버에서만 씁니다.

## 실행 방법

Node.js 20 이상이 필요합니다.

```bash
git clone https://github.com/sangxxjin/ject-hackathon-2026.git
cd ject-hackathon-2026
npm install
cp .env.example .env.local
```

`.env.local`에 키를 넣습니다. 이 파일은 커밋되지 않습니다.

```
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4o-mini
JUDGE_SOURCE=hybrid   # hybrid(기본) / ai / curated
```

```bash
npm run dev
```

브라우저에서 http://localhost:3000 을 엽니다. 배포 전에는 `npm run build`로 빌드를 확인합니다.

## 판독 결과가 만들어지는 방식

`POST /api/judge` 한 번으로 리빌, 세 가지 모드 문구, 오늘의 처방이 모두 정해집니다. `JUDGE_SOURCE`로 방식을 고릅니다.

| 방식 | 사실(선수·연도·기록) | 문구(위로·동기부여·독설·처방) | 응답 시간 |
| --- | --- | --- | --- |
| **`hybrid` (기본)** | 팀이 준비한 기록 (`lib/fallback.ts`) | AI가 매번 새로 씀. 9초 안에 안 오면 템플릿 문구 | 약 3~4초 |
| `ai` | AI가 웹 검색으로 찾음, 출처 링크 표시 | AI | 10~37초 |
| `curated` | 준비한 기록 | 템플릿 문구 | 즉시 |

- AI 호출이 실패하거나 늦으면 준비한 기록과 템플릿 문구로 넘어갑니다. `/api/judge`가 아예 응답하지 않으면 클라이언트가 같은 데이터로 결과를 만듭니다.
- 브라우저마다 10분에 20번까지 AI를 부르고, 넘으면 준비한 기록으로 답합니다 (`lib/ratelimit.ts`).

**실시간 발굴 (하이브리드에서 선수 풀 넓히기)**

- 판독 응답을 보낸 **뒤** 서버가 웹 검색(gpt-5-mini)으로 그 종목·나이의 새 기록을 찾아 Upstash Redis에 쌓습니다. 사용자는 기다리지 않습니다.
- 생년월일과 사건 날짜로 나이를 서버가 계산하고, 출처 주소가 실제 검색 기록에 있어야 저장합니다. **같은 기록이 두 번 따로 나와야** 판독에 쓰이고, 그때는 "AI가 웹에서 찾은 기록이에요"와 출처 링크가 붙습니다.
- 그 나이 기록이 이미 충분하거나, 10분 안에 같은 종목·나이를 찾았거나, 하루 한도(`DISCOVERY_DAILY_LIMIT`, 기본 50)를 넘으면 부르지 않습니다.
- 규칙과 저장 형식은 [docs/spec.md](docs/spec.md) 7.9에 있습니다.

**리빌 선수를 고르는 규칙**

- **처음 판독:** 사용자 나이와 가장 가까운 기록 중 슈퍼스타(fame 1)를 고릅니다.
- **다시 올수록:** 나이 허용 폭을 넓히고(최대 ±4살) 팬이라면 아는 스타(fame 2)도 섞습니다. 하이브리드 문구의 temperature도 0.8에서 최대 1.0까지 올립니다.
- **최근 본 선수 제외:** 브라우저에 판독 횟수와 최근 선수 5명을 저장해서(`lib/history.ts`) 다음 날 와도 어제 본 선수를 피합니다.
- 기록은 6종목 79개입니다. 표와 규칙은 [docs/fallback.md](docs/fallback.md)에 있습니다.

## 판독 결과 변경 이력

| 순서 | 변경 | 이유 |
| --- | --- | --- |
| 1 | **AI 웹 검색 판독**으로 시작. 프롬프트 사실 규칙, 서버 검증(출생 연도 + 사건 연도 = 당시 나이 등), 실패 시 비상용 결과 | 선수 기록 DB 없이 어떤 종목·나이든 결과를 내려고 |
| 2 | 응답 길이 제한과 재시도 추가 | gpt-4o-mini가 가끔 제어 문자를 반복하며 JSON이 깨짐 |
| 3 | 모델 실측: gpt-4o-mini + 웹 검색은 8건 중 4건만 성공하고 사실 오류가 섞임. gpt-5-mini는 정확하지만 25~37초 이상 | 이 키로는 "빠르고 정확한" 조합이 없음 ([docs/spec.md](docs/spec.md) 2절) |
| 4 | **하이브리드를 기본값으로.** 사실은 준비한 기록, AI는 문구만 | 틀린 사실은 막고 매번 다른 문구는 유지. 응답이 3~4초로 줄어듦 |
| 5 | 오늘의 처방을 모드별 강도로 다양화, 처방 스톱워치와 운동 시간 OVR 보너스 | 처방이 늘 같은 문장이었음 |
| 6 | 위로 모드 보조 문구를 나이별 실제 기록으로 표시 | 보조 문구와 위로 문장이 따로 놀았음 |
| 7 | 브라우저별 AI 호출 제한 | 시연장 공유 IP로 전체가 막히지 않게, 비용 폭주 방지 |
| 8 | **첫 판독은 슈퍼스타, 재방문할수록 다양한 선수.** 기록 52개 → 79개, 유명도 등급, 방문 횟수 저장 | 같은 나이로 다시 하면 82% 확률로 같은 선수가 나왔음 |
| 9 | **실시간 발굴.** 판독 뒤 백그라운드에서 gpt-5-mini가 웹 검색으로 새 기록을 찾고, 두 번 확인되면 판독에 씀 (Upstash Redis) | 준비된 기록 79개 밖의 선수도 나오게, 사용자는 기다리지 않게 |

## 판독 품질 테스트

실제 사용자처럼 `/api/judge`에 요청을 보내 AI 답과 미리 지정한 답의 비율, 정확성, 문구 품질, 반복 정도를 잽니다. 개발 서버를 켠 상태에서 실행합니다.

```bash
node --no-warnings scripts/eval-judge.mjs
```

`--judge`를 붙이면 OpenAI가 재미·톤·사실을 1~5점으로 채점하고(비용 발생), `--base 배포주소`로 배포본을 잽니다. 결과는 `eval/results/`에 저장됩니다(커밋하지 않음). 옵션은 스크립트 맨 위 주석에 있습니다.

**최근 결과 (2026-11-14, 하이브리드, 로컬)**

| 항목 | 변경 8 이전 | 변경 8 이후 |
| --- | --- | --- |
| AI 문구 비율 (나머지는 템플릿) | 99% | 99% |
| 정확성 규칙 통과 | 92% | 94% |
| 같은 종목·나이로 다시 했을 때 같은 선수 | 82% | 35% |
| 첫 판독에 슈퍼스타 | - | 100% |
| 위로·동기부여·독설 문구가 똑같이 나온 비율 | 0% | 0% |

**남은 문제**

- 독설이 사용자 나이를 건드리는 문장이 가끔 나옵니다(예: "아직 젊으니!"). 하이브리드 문구 프롬프트(`lib/hybrid.ts`)에서 더 막아야 합니다.
- 반말이나 영어 단어가 섞인 문구가 일부 있습니다.
- 준비한 기록은 모두 `verified: false`입니다. 팀이 출생일과 연도를 확인해야 합니다.
